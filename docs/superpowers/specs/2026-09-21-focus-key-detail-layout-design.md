# Focus: layout списка и деталей виртуального ключа

## Цель

Сделать рабочее пространство виртуальных ключей удобным в обоих состояниях:

- пока ключ не выбран, список занимает всё доступное место;
- после выбора появляется панель деталей, которой выделено больше места, чем списку.

## Поведение

`FocusVirtualKeysPage` определяет состояние по `selectedKeyId`.

- Если ключ не выбран, контейнер списка использует всю ширину доступной рабочей области. Правая панель не рендерится и не резервирует пустое место.
- Если ключ выбран, отображается двухколоночная сетка с фиксированным соотношением: список — 40%, детали — 60%.
- Размер колонок не меняется пользователем: перетаскиваемый разделитель не добавляется.
- На узких экранах сохраняется существующее вертикальное представление, чтобы не сжимать таблицу и форму деталей до нечитаемого состояния.
- Закрытие детали возвращает полноширинный список.
- По уточнению пользователя боковой блок «Команды» удаляется. Пропорция 40%/60% считается от полной ширины рабочей области.
- Фильтр по команде остаётся в существующей панели фильтров.
- По последующему уточнению пользователя burger-меню реализуется сейчас и доступно на широком и узком экране. В нём единственный активный пункт «Виртуальные ключи». Пунктов «Команды», заглушек и другой навигации пока нет. Существующий компонент меню служит каркасом для будущих пунктов старого UI.

## Границы

Изменяется только раскладка нового маршрута `/new-ui`. Поиск, фильтры, сортировка, выбор колонок, URL-состояние, создание ключа и существующий `KeyInfoView` не меняют поведение.

## Проверка

Проверить штатной production-сборкой dashboard. Новые тесты не добавлять по явному требованию пользователя.
